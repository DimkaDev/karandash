# SiteForge: план Phase 0

Дата: 2026-10-26. Статус: предлагается к проверке, реализация не начата.
Основание: spec.md v1.2 одобрен основателем в чате 2026-10-25. Статус в заголовке spec.md пока исторический; настоящее решение об одобрении зафиксировано здесь.

## Результат и границы

Предприниматель заказывает демо на странице FR/EN. Основатель входит по magic link, открывает заявку, генерирует и проверяет сайт, затем явно подтверждает отправку письма с временной ссылкой. Сервис фиксирует отправку и ответ, стоимость генерации и данные для G1.

Первый демонстрируемый срез: вход основателя → ручной brief → генерация → предпросмотр. Второй: публичная заявка → тот же рабочий процесс → доставка демо.

Не входят: публичный автоматический Sandbox, полноценный редактор, клиентские аккаунты, production-сайты клиентов, платежи, запись и магазин. Автоматические follow-up письма не строим: основатель отправляет разрешённые сообщения вручную, с фиксацией согласия и числа контактов. Без G1 Phase 1 не начинается.

## Зафиксированные решения

- Quarkus + PostgreSQL + Qute; Angular для публичной формы и небольшой панели. Одна кодовая база и модульный монолит, без брокера сообщений.
- Принятая карта: foundation → demo-factory → demo-requests → demo-sharing → launch-operations. Request intake может разрабатываться после foundation независимо от генерации, но итоговый порядок задач последовательный для одного исполнителя.
- Защищённый web inbox; одноразовый magic link только на allowlisted email основателя; secure HttpOnly session, CSRF для изменений. Для разработки используется локальный email sink; публичного обхода аутентификации нет.
- Перед отправкой демо основатель видит preview сайта и письма и подтверждает действие. Используем provider idempotency, если он доступен; неопределённую доставку не повторяем вслепую.
- AI создаёт JSON, не код. Начальный адаптер Anthropic из OD-3, mock по умолчанию локально. Настоящие provider/model IDs и тарифы фиксируются при оценке; платный вызов без настройки ключа и бюджета запрещён.
- Все сгенерированные файлы приватны. Публичный content-домен обслуживает HTML и связанные ресурсы только через проверку capability; revocation/expiry действуют на каждый запрос, без обхода через storage/CDN.
- Одновременно резервируем максимальную оценку стоимости вызова в PostgreSQL; учитываем classification, generation и repair. Для Phase 0 предел AI €30/месяц, общий предел €500/месяц; отдельный дневной бюджет Sandbox относится к Phase 1.
- Приняты EU VPS, Docker Compose и Caddy. Выбор поставщиков email/storage/bot-check, цены, регионы и процессоры подтверждаются до production-настройки; локальные адаптеры позволяют работать до этого.

## Контракты поведения

- `POST /api/v1/auth/magic-link`: одинаковый публичный ответ независимо от разрешённости email; письмо только разрешённому адресату. Погашение выполняется отдельным POST после открытия страницы, чтобы email-scanner GET не расходовал токен. Logout отзывает сессию.
- Studio endpoints работают только с сессией: prospects/projects, blueprint/generate, polling jobs, preview, demo-links, inbox и fulfilment. Маршруты и error shape из section 12 фиксируются в OpenAPI до кода соответствующего endpoint.
- `POST /public/v1/demo-requests`: валидирует поля section 21.3, consent version, bot token и idempotency key. Одинаковый ключ/тело возвращает тот же receipt, другое тело с тем же ключом даёт conflict. Receipt не раскрывает inbox или brief.
- Fulfilment: RECEIVED → IN_PROGRESS → DELIVERED; ошибка попытки хранится отдельно с возможностью повтора, WITHDRAWN запрещает отправку. Несколько кликов не создают параллельные jobs/письма. DELIVERED означает принятие письма провайдером, не доказанное чтение человеком.
- `GET /d/{token}` и приватные asset routes: непрозрачный случайный токен ≥128 бит, хранится hash, срок 14 дней; expired/revoked дают 410, неизвестный токен 404. No-store, noindex и no-referrer; token не попадает в application/access logs. Публичного origin URL нет.
- Demo-view counts приблизительные, с фильтрацией известных ботов и preview основателя; уникальных людей не обещаем. Ответ, звонок и вопрос о цене фиксируются основателем.
- Удаление: неотправленные заявки 30 дней от получения, отправленные 60 дней от доставки; withdrawal прекращает отправки сразу, удаляет связанные данные в пределах 7 дней. Expired demo files очищаются через 7 дней, доступ прекращается при expiry. Backup restore повторно применяет deletion ledger до открытия сервиса.
- Demo quote/contact/booking/shop элементы не принимают реальные обращения и не обещают действующую услугу: видимая маркировка, безопасное объяснение при активации. Production-формы клиентов не входят в Phase 0.

## Проверка и запуск

Backend: JUnit/Quarkus tests, PostgreSQL Testcontainers, Flyway migrations. Frontend: Angular unit runner, Playwright для browser flows, axe для автоматической части accessibility; отдельная ручная проверка клавиатуры, focus, labels и contrast. Оценка модели по section 11.5 с FR/EN fixtures, отдельный ручной language review.

Команды ниже пока контракты для scaffold, не существующие успешные проверки. Каждая bootstrap-задача должна сделать свой контракт исполнимым. Проверки на реальном провайдере запускаются отдельно от CI с mocks, с измерением стоимости.

Порядок запуска: локальный mock → локальная настоящая генерация с budget cap → закрытый staging на синтетических данных → restore/security/full-flow проверки → реальные данные после notices/processor readiness → реклама только после G0 preflight. G1: минимум 10 запросов реальных компаний за 6 недель и минимум 3 содержательных ответа на доставленные демо по spec.md. Счётчик fetch не заменяет этот критерий.

## Нерешённые входные данные и риски

| Вопрос | Действие / блокирует |
| --- | --- |
| Визуальный бриф | Основатель выбрал guided brief; P0-01 фиксирует его ответы. Не изобретать DESIGN.md от его имени. UI implementation заблокирован до брифа, backend продолжает работу |
| Email, domains, provider accounts | Основатель предоставляет реальные значения вне репозитория; P0-31. Никаких покупок или внешних отправок в рамках планирования |
| Точные версии и модели | P0-02/03 фиксируют совместимые стабильные версии и lockfiles; P0-17 фиксирует model IDs после eval. Не переносить непроверенные номера версий из чата |
| Email delivery uncertainty | Idempotency и reconciliation; неизвестный результат требует проверки перед повтором |
| Детерминированный grounding неполон | Ограниченные поля/шаблоны, regression fixtures и обязательная проверка основателем; не обещать доказанное отсутствие любых выдумок |
| Private assets и expiry | Проверка каждого asset route; тест прямого доступа к origin, revoke и expiry |
| Budget estimates | Reservation до вызова + actual usage reconciliation; uncertain cost не освобождается автоматически |
| Noindex не защита доступа | Capability token и приватный origin; никаких персональных данных в URL кроме случайного токена |
| Готовность к рекламе | Реальные notices, операторские данные, processor records, employer check и cap подтверждаются основателем; эта разработка не означает юридическую готовность |

## Граница одобрения

План и задачи требуют проверки основателем перед реализацией. Уточнение структуры проекта и версии инструментов не меняют утверждённую бизнес-модель. Изменение бюджета, gate thresholds, набора фаз или operating/privacy policy требует отдельного решения. Полный UI delivery gate выполняется на работающем продукте; этот документ не выдаёт дизайн или runtime за проверенный результат.
